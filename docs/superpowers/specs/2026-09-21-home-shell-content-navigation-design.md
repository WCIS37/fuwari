# Minerhut 主页内容舞台设计

## 目标

把 Minerhut 从视觉上仍会切换整页的博客改造成以主页为固定外壳的内容浏览体验。Zephyr 氛围背景、顶部导航和左侧手账栏在站内导航期间保持稳定，首页文章列表、文章正文、归档和关于内容只在右侧内容舞台中平滑切换。

项目继续输出独立静态页面和独立 URL，不改造成纯客户端 SPA。文章链接、归档和关于页面必须支持分享、浏览器前进后退、直接访问、直接刷新、搜索引擎索引及 Cloudflare Pages 静态托管。

## 用户可见行为

- 顶部导航显示“首页”“归档”“关于”；外部 GitHub 名称保持不变。
- 点击文章后，地址更新为 `/posts/<slug>/`，右侧从文章列表切换为文章正文。
- 点击“归档”后，地址更新为 `/archive/`，右侧显示归档内容。
- 点击“关于”后，地址更新为 `/about/`，右侧显示关于内容。
- 顶部导航、首页氛围背景、个人资料、分类和标签侧栏不随右侧内容重新加载或重新播放入场动画。
- 大屏文章目录继续显示在右侧既有 TOC 区域。
- 当前导航项具有明确但克制的选中状态。
- 浏览器前进和后退恢复对应 URL 与内容。
- 直接打开任意文章、归档或关于 URL 时，服务端输出完整主页外壳和对应内容。

## 方案选择

采用 Astro 静态页面加 Swup 局部替换，不引入新的客户端路由器。

不采用以下方案：

- 纯 Svelte SPA：会迫使文章渲染、SEO、Pagefind 和直接访问逻辑迁移到客户端，复杂度和风险过高。
- 把所有正文预先放进首页：会使首页体积随文章数量线性增长，并削弱独立 URL 和索引行为。

## 页面结构

所有由 `MainGridLayout.astro` 渲染的路由共享同一结构：

```text
固定主页外壳
├── Zephyr 日夜氛围背景
├── 顶部导航
├── 左侧个人资料 / 分类 / 标签
├── 右侧内容舞台（Swup 替换）
│   ├── 首页文章列表与分页
│   ├── 文章正文
│   ├── 归档
│   └── 关于
└── 大屏文章目录（Swup 同步替换）
```

首页氛围背景不再只由根路径条件渲染。任何站内内容 URL 初次加载时都必须得到相同外壳，避免直接进入文章时缺少主页背景与侧栏。

Swup 的主要替换容器恢复为右侧 `main` 内容舞台，同时继续同步替换 `#toc`。导航栏、背景和侧栏位于这些容器之外，因此站内切换不会重建它们。

## 路由与数据流

1. 用户点击文章、首页、归档或关于链接。
2. Swup 拦截同源链接，并请求目标静态 HTML。
3. URL 通过 History API 更新为目标地址。
4. Swup 从响应中提取右侧内容舞台和 TOC。
5. 旧内容执行退场动画，容器内容被替换，新内容执行入场动画。
6. 内容相关功能在 Swup 生命周期中重新初始化。
7. 请求或替换失败时，链接退回浏览器正常导航。

页面内容继续由现有 Astro 路由在构建时生成。文章正文、归档数据与关于 Markdown 不新增重复的数据获取通道。

## 动画设计

- 退场：内容降低透明度，并向左上方移动少量距离。
- 入场：新内容从右下方轻微上移并淡入。
- 动画位移保持克制，避免与背景视差和标题滚动动画竞争。
- 切换期间显示低对比度蓝绿色流光进度提示；快速响应时不应产生明显闪烁。
- 切换完成后滚动到内容舞台顶部。
- `prefers-reduced-motion: reduce` 下取消位移，仅进行快速透明度切换或立即替换。
- 固定外壳不得重新播放首次加载动画。

## 导航状态

导航名称调整为：

- Home → 首页
- Archive → 归档
- About → 关于

选中状态根据当前 URL 推导：

- `/` 和分页路径对应“首页”。
- `/archive/` 对应“归档”。
- `/about/` 对应“关于”。
- 文章 URL 不强行选中“首页”，避免把内容类型和返回入口混淆。

选中状态必须在直接加载和 Swup 导航完成后保持一致。

## 内容功能生命周期

Swup 替换后需要保证以下功能可用：

- 文章目录及滚动高亮。
- 图片 PhotoSwipe 灯箱。
- 代码块复制等 Expressive Code 行为。
- 归档页的 Svelte 交互。
- Pagefind 搜索面板。
- 返回顶部按钮及自定义滚动条。
- 首页背景的指针视差和标题滚动效果，只初始化一次并避免重复监听。

初始化函数应具有幂等性；重复的 Swup 生命周期事件不得叠加监听器。

## 响应式行为

- 桌面端保持左侧手账栏和右侧内容舞台布局。
- 移动端沿用当前网格顺序，侧栏与内容区按既有响应式规则排列。
- 移动端菜单中的首页、归档和关于链接使用相同的 Swup 导航。
- 页面切换不得造成横向滚动、布局跳跃或背景短暂露白。

## 错误处理与渐进增强

- 所有站内入口保留真实 `href`，不能依赖 JavaScript 才可访问。
- Swup 尚未加载、被禁用或导航失败时，浏览器执行正常页面跳转。
- 服务端/静态 HTML 始终包含完整可读内容。
- 不在首页预加载全部文章正文。

## 测试与验收

自动测试覆盖：

- 中文导航文本与正确链接。
- Swup 仅替换内容舞台和 TOC。
- 所有路由均输出固定主页外壳。
- 内容切换动画与减少动态效果样式。
- 固定外壳脚本不会因导航重复注册。

手动或浏览器级验收覆盖：

- 首页 → 文章 → 首页。
- 文章 A → 文章 B。
- 首页 → 归档 → 文章。
- 首页 → 关于 → 返回。
- 浏览器前进、后退和直接刷新。
- 桌面端与移动端。
- `prefers-reduced-motion`。
- 生产构建后的文章目录、图片灯箱、归档交互和 Pagefind。

完成标准：现有首页视觉保持不变，站内内容切换无整页闪烁，独立 URL 与静态部署能力保持完整，相关自动测试、Astro 检查和生产构建通过。
